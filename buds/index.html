Many earbuds send settings over classic Bluetooth serial (SPP), which Web Bluetooth can't reach. Desktop Chrome can open a paired device's SPP channel through Web Serial.

Why commands need mapping. realme hasn't published the buds' control protocol, so ANC, EQ and gesture commands are vendor bytes. Battery, model and firmware use standard Bluetooth services and work right away if the buds expose them.

Capture the bytes on Android:

  1. Developer options → turn on Enable Bluetooth HCI snoop log, then toggle Bluetooth off and on.
  2. In the realme Link app, tap one setting at a time (e.g. ANC on, then off) and note the time.
  3. Run adb bugreport, open btsnoop_hci.log in Wireshark.
  4. Filter btatt.opcode == 0x52 || btatt.opcode == 0x12 for BLE writes, or btrfcomm for SPP.
  5. Copy the characteristic UUID and payload hex into the Command map.

Hosting. Web Bluetooth needs HTTPS. Put this file on GitHub Pages and open it in Chrome. iPhone browsers don't support Web Bluetooth.
